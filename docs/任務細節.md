# Rate 計算說明

**Rate = bit left / total bit**，衡量 LiveKVQuant-P 相對於 FP16 fullKV 的 KV Cache 位元使用比例。

## 公式

```
r = outlier_ratio = 0.01
chunk_size = 512
n_warmup = 2

N = ceil(avg_tokens / chunk_size)

Rate = (n_warmup/N × 16 + (N - n_warmup)/N × (4 + r×48 + 16/chunk_size)) / 16
```

### 各項說明

| 項目 | 說明 |
|---|---|
| `n_warmup/N × 16` | Warm-up 階段（前 2 chunks）保持 FP16，rate=1 |
| `(N-n_warmup)/N × (4 + r×48 + 16/512)` | 量化後的 chunks |
| `4` | INT4 量化的 4 bits |
| `r×48 = 0.01×48` | Outlier 1% 保留 FP16（16 bits）相對於 INT4（4 bits）的額外成本：0.01×(16−4)=0.12，但展開成 `r×48` 因為分母是 16 |
| `16/chunk_size = 16/512` | Scale 參數（per-channel min/max）的額外成本均攤 |

> **注意：** avg_tokens 為 tokenizer encode 後的有效 token 數。LongBench v2 因為長度超過 model max_position_embeddings (131072)，會做 head+tail truncation，實際 effective tokens = min(raw_tokens, 130908)（= 131072 - output_len_64 - buffer_100）。

## LongBench v2 結果

> LongBench v2 的 prompt 由 `context + question + choices (A/B/C/D)` 組成。
> 因部分樣本超過 131072 tokens，實際 effective tokens = min(raw_tokens, **130908**)。

| Task | N (samples) | Avg Tokens (eff) | N Chunks | Rate | Target Token |
|---|---|---|---|---|---|
| Single-Document QA | 175 | 73,385 | 144 | 29.19% | 21,421 |
| Multi-Document QA | 125 | 72,240 | 142 | 29.21% | 21,101 |
| Long In-context Learning | 81 | 104,447 | 204 | 28.90% | 30,185 |
| Long-dialogue History Understanding | 39 | 73,847 | 145 | 29.19% | 21,556 |
| Code Repository Understanding | 50 | 113,030 | 221 | 28.85% | 32,609 |
| Long Structured Data Understanding | 33 | 121,409 | 238 | 28.80% | 34,966 |

### 觀察
- v2 任務的 token 數普遍遠大於 v1（多數 7~12 萬，部分超過 130k 被截斷）
- N 大（140~238 chunks），warmup 比例極小，rate 收斂在 **~28.8%~29.2%**
- v1 短任務（如 multi_news N=6, rate=52%）在 v2 完全不出現，v2 壓縮效果更穩定
